# 选题逻辑与内容结构

## 1. 选题输入卡

开始写作前，用最少字段确定方向：

| 字段 | 要回答的问题 |
|---|---|
| 目标客户 | 组装厂、OEM、外贸商、经销商还是售后渠道？ |
| 发生场景 | 装机、采购、交付、转售、换件、远程售后还是品牌上市？ |
| 经营损失 | 返工、延期、退换、利润流失、信任下降还是品牌无法沉淀？ |
| 解决机制 | 哪个产品能力或服务流程真正改变了这件事？ |
| 信任依据 | 客户能看到或检查什么？ |
| 主要结果 | 这条内容只让客户记住哪个好处？ |
| CTA | 客户下一步提交什么、获得什么？ |

选题公式：

> 目标客户＋具体场景＋经营损失＋解决机制＋信任依据＋客户结果

## 2. 六段主线

### 客户处境

描述客户正在经历的事实。不要从“我们支持”开始。

### 经营影响

说明这件事为什么值得解决。优先写客户真正承担的时间、交付、售后、利润或品牌影响。

### 信任依据

给出可展示的页面、样机、清单、记录、教程、测试或流程。信任依据应出现在提出方案之前或同时出现。

### 解决机制

将方案写成连续动作，而不是功能清单。例如：

> 扫码识别设备 → 显示适配配件 → 进入授权购买入口 → 售后沿用同一设备记录

### 客户结果

回到开头的问题，只保留一个主要结果。结果应是客户能感受到的改变，而不是“功能实现”。

### 具体行动

CTA说明客户需要提供什么以及能够得到什么。避免“联系我们了解更多”。

## 3. 逻辑压缩方法

先写完整因果链，再压缩：

1. 删除重复背景，只保留一个典型场景。
2. 合并同义功能，保留改变客户工作方式的动作。
3. 合并重复收益，只保留与开头痛点直接对应的结果。
4. 保留必要的连接词和中间步骤；不要为了短而切断因果。
5. 一个镜头可以承载半句或一段话，口播结构不必机械服从镜头数量。

## 4. 默认时长

| 时间 | 任务 |
|---|---|
| 0至5秒 | 客户熟悉的处境或冲突 |
| 5至12秒 | 对经营造成的影响 |
| 12至25秒 | 信任依据和解决机制 |
| 25至38秒 | 方案怎样运行 |
| 38至45秒 | 一个客户结果 |
| 45至50秒 | 具体CTA |

默认使用6至8镜。若用户指定60秒或参考模板，应以用户要求为准，但删除重复解释。

### 逐镜口播时长核算

交付前必须逐镜核算，不能根据句子长短凭感觉填写时间：

- 中文自然商务口播可先按每分钟220至260个有效字符估算。
- 英文自然商务口播可先按每分钟130至150词估算。
- 每个完整句子额外预留约0.3至0.5秒停顿；强调、数字、型号和专业词还应适当留时。
- 中英文使用同一时间轴时，每一镜都要按较慢的语言版本安排，不能只看整条视频的总字数。
- 某一镜超时时，优先删除重复信息或改写表达；关键因果不能为了赶时长被删掉。
- 估算只用于脚本校核。进入配音或剪辑后，应以实际录音或最终TTS音频再次确认，并据此微调镜头点位。

建议在内部校核表中记录：`镜号｜设定秒数｜中文字数｜中文预计秒数｜英文词数｜英文预计秒数｜是否通过`。最终交付是否展示该表，可按用户要求决定。

## 5. 画面映射

- 客户处境：订单、配件、装机、沟通或交付的真实场景。
- 经营影响：返工、等待、退换、重复沟通等简单流程或对比。
- 信任依据：真实系统页面、样机、清单、记录或教程。
- 解决机制：用连续流程动画解释动作之间的关系。
- 客户结果：用前后变化展示，不堆叠多个收益词。
- CTA：展示客户能够获得的具体材料。

实拍优先。没有真实页面时使用明确标注的页面示意；没有客户案例时不要用AI画面冒充案例。

## 6. CTA类型

- 配置核对：提交机型、供电、接口、协议和现有配件，获得适配核对。
- 配件管控：提交市场和渠道模式，获得扫码字段或流程清单。
- OEM：提交目标市场、预计数量和品牌需求，获得品牌样机确认清单。
- 售后：提交配置、现象和飞行记录，进入远程排查。

CTA承诺的材料或动作必须实际能够提供。
